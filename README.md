# myInvoices Starter v0.5.0

Νέα ανεξάρτητη βάση εφαρμογής για λογιστές, βασισμένη στις απαιτήσεις και στην αρχική ανάλυση του myInvoices. **Δεν είναι ο ανακτημένος πηγαίος κώδικας της παλιάς εφαρμογής.**

## Τι λειτουργεί σε αυτή την έκδοση

- Απλό ελληνικό γραφικό περιβάλλον Tkinter/ttk.
- Πελάτες με διαφορετικό ΑΦΜ και ξεχωριστή κατάσταση ανά περιβάλλον ΑΑΔΕ.
- SQLite για παραστατικά, XML, οικονομικά στοιχεία, επίσημο `downloadingInvoiceUrl`, πρόοδο και ιστορικό επιτυχών σελίδων.
- `RequestDocs` adapter με χρονικό όριο, σταθερούς HTTPS προορισμούς, απαγόρευση redirects και ασφαλή μηνύματα σφαλμάτων.
- Συγχρονισμός πολλών σελίδων, αποφυγή διπλότυπων και συνέχιση μετά από διακοπή.
- Αποθήκευση ακυρώσεων, χαρακτηρισμών και πληρωμών ως ξεχωριστές μεταβολές με το αρχικό XML τους.
- Αναζήτηση πελατών χωρίς διάκριση τόνων, πλαίσιο πλήρων σφαλμάτων και αντιγραφή με ένα κουμπί.
- Αποθήκευση σελίδας και προόδου σε κοινή συναλλαγή. Αποτυχημένη σελίδα επαναλαμβάνεται χωρίς να χάνεται.
- Offline demo με συνθετικά δεδομένα και χωρίς καμία δικτυακή σύνδεση.

- Άμεση λήψη PDF από τα επίσημα links του myDATA, χωρίς αποστολή των AADE credentials στους παρόχους.
- Διαχωρισμός ανά πελάτη/περιβάλλον, έτος, μήνα και ΑΦΜ προμηθευτή· MARK στο όνομα αρχείου.
- Έλεγχος δομής PDF με pypdf, πρόοδος, διακοπή και καταγραφή κατάστασης ανά παραστατικό. Δεν αντικαθίστανται υπάρχοντα αρχεία.
- Επαναληπτική λήψη παραλείπει αποθηκευμένο αρχείο μόνο αφού ελέγξει μέγεθος και SHA-256. Διαγραμμένα/αλλοιωμένα αρχεία μπορούν να ληφθούν ξανά.

**Δεν υλοποιούνται ακόμη OCR, ευρετήριο ηλεκτρονικής αρχειοθέτησης, Excel ή EXE.** Cloudflare/CAPTCHA και ιστοσελίδες εμφανίζονται ως εκκρεμότητες· δεν παρακάμπτονται. Η συσχέτιση MARK/link διατηρείται από myDATA, αλλά δεν γίνεται ακόμη ανεξάρτητος έλεγχος του περιεχομένου PDF.

### Λήψη PDF

1. Άνοιξε πρώτα `INSTALL.bat` μία φορά (χρειάζεται σύνδεση για τη δωρεάν βιβλιοθήκη pypdf).
2. Άνοιξε `START_MYINVOICES.bat`, επίλεξε πελάτη και κάνε συγχρονισμό.
3. Πάτησε **Λήψη PDF περιόδου** και διάλεξε φάκελο προορισμού.
4. Τα αρχεία αποθηκεύονται στο `<προορισμός>/<ΑΦΜ>_<περιβάλλον>/ΠΡΟΣ_ΕΛΕΓΧΟ/<έτος>/<μήνας>/<ΑΦΜ προμηθευτή>/`.

Κατεβαίνουν μόνο παραστατικά με διαθέσιμο link και χωρίς γνωστή ακύρωση. Όριο 40 MB/500 σελίδες, HTTPS/443 με ελεγμένα redirects, timeout ανά δικτυακή αναμονή 30s. Η διακοπή περιμένει την τρέχουσα αναμονή δικτύου· τα ήδη ολοκληρωμένα αρχεία διατηρούνται. Η επιλογή φακέλου γίνεται σε κάθε παρτίδα. Το OCR θα προστεθεί για αναζήτηση και ηλεκτρονική αρχειοθέτηση, όχι ως προϋπόθεση λήψης.

### Ημερομηνίες και άντληση περιόδου

Συμπλήρωσε **Από / Έως** ως `01/01/2026` / `31/12/2026` και πάτησε **Εφαρμογή** για προβολή των ήδη αποθηκευμένων παραστατικών. Η περίοδος αφορά την ημερομηνία έκδοσης, περιλαμβάνει και τις δύο άκρες και εφαρμόζεται επίσης στη **Λήψη PDF περιόδου**.

Με συμπληρωμένες και τις δύο ημερομηνίες, ο **Συγχρονισμός επιλεγμένου** στέλνει `dateFrom`/`dateTo` στο RequestDocs. Κρατά ανεξάρτητη πρόοδο/continuation ανά πελάτη και ακριβή περίοδο· δεν προωθεί το MARK του γενικού συγχρονισμού. Επανάληψη της ίδιας περιόδου συνεχίζει από τη δική της πρόοδο. Το **Όλες οι ημερομηνίες** επιστρέφει στον γενικό συγχρονισμό. Μία μόνο άκρη επιτρέπεται για τοπική προβολή/λήψη PDF, αλλά η άντληση ΑΑΔΕ χρειάζεται και τις δύο. Οι μεταβολές/ιστορικό εμφανίζονται συνολικά για τον πελάτη, χωρίς το φίλτρο ημερομηνίας των παραστατικών.

### Όταν ο πάροχος εμφανίζει σελίδα ή CAPTCHA

Το συγκεντρωτικό μήνυμα λήψης αναφέρει πλέον πλήθος ανά αιτία, π.χ. HTTP 403, CAPTCHA, HTML ή μη έγκυρο PDF. Τα 15 «εκκρεμή» της προηγούμενης έκδοσης δεν αποδεικνύουν ότι είναι όλα Cloudflare.

1. Επίλεξε **ένα παραστατικό** στη λίστα.
2. Πάτησε **Άνοιγμα επιλεγμένου στον browser**. Ανοίγει ο ακριβής σύνδεσμος myDATA στον κανονικό προεπιλεγμένο browser σου.
3. Ολοκλήρωσε τυχόν έλεγχο στη σελίδα και κατέβασε το PDF με τις επιλογές του παρόχου.
4. Με το ίδιο παραστατικό επιλεγμένο, πάτησε **Εισαγωγή PDF από browser**, διάλεξε το αρχείο και επιβεβαίωσε MARK/πελάτη/προμηθευτή.
5. Διάλεξε φάκελο αρχειοθέτησης. Το PDF ελέγχεται και αντιγράφεται στη δομή πελάτη/περιβάλλοντος/ημερομηνίας/προμηθευτή. Το αρχικό αρχείο διατηρείται. Εμφανίζεται «PDF από browser — προς έλεγχο».

Αυτή είναι χειροκίνητη επιβεβαίωση και εισαγωγή, όχι αυτόματη επίλυση CAPTCHA ή αυτόματη παρακολούθηση του φακέλου Downloads. Δεν αντιγράφονται cookies ή κλειδιά από τον browser. Το `turnstile_solver` που προτάθηκε εξετάστηκε ως πηγή αναφοράς, αλλά δεν προστέθηκε ως εξάρτηση και δεν εκτελέστηκε· δεν έχει αποδειχτεί συμβατότητα με τους συγκεκριμένους παρόχους.

Η βάση αναβαθμίζεται μη καταστροφικά σε schema 4 με αυτόματο αντίγραφο ασφαλείας (`*-schema3-backup-*.sqlite3` για την v0.4). Διατηρούνται πελάτες, κλειδιά, παραστατικά και προηγούμενες λήψεις.

## Windows — ασφαλής πρώτη εκτέλεση

Απαιτείται Python 3.11+ με Tkinter. Αυτή είναι έκδοση πηγαίου κώδικα· δεν είναι αυτοτελές EXE. Η λήψη/οι δοκιμές PDF χρειάζονται τη δωρεάν βιβλιοθήκη του `requirements.txt`.

Αποσυμπίεσε το project σε νέο φάκελο, όχι επάνω στην παλιά εφαρμογή. Άνοιξε PowerShell στον φάκελο που περιέχει αυτό το README:

```powershell
py -0p
git --version
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m myinvoices --check-demo
.\.venv\Scripts\python.exe -m myinvoices --demo
```

Δεν χρειάζεται activation της virtual environment ή αλλαγή PowerShell execution policy. Αν λείπει το Git, το ZIP λειτουργεί και χωρίς αυτό. Αν δεν υπάρχει `py`, χρησιμοποίησε τη διαδρομή του διαθέσιμου Python interpreter.

Μετά τη δημιουργία της `.venv`, άνοιξε **START_MYINVOICES.bat**: η κανονική λειτουργία έχει ενεργά πεδία API στα στοιχεία κάθε πελάτη. Τα `run_live.bat` και το παλιό `run_demo.bat` ανοίγουν επίσης την κανονική λειτουργία, ώστε παλιές συντομεύσεις να μη σε παγιδεύουν στο demo. Μόνο το **demo_only.bat** ή το ρητό `--demo` ανοίγει συνθετικά δεδομένα.

### Μέσα στο demo

1. Υπάρχει ήδη ο «Συνθετικός πελάτης DEMO», ΑΦΜ `000000000`.
2. Πάτησε **Συγχρονισμός επιλεγμένου**.
3. Εμφανίζονται δύο συνθετικά παραστατικά σε δύο σελίδες άντλησης.
4. Το ένα γράφει «Υπάρχει link — PDF ανεξέλεγκτο» και το άλλο «Χωρίς link PDF».
5. Ξαναπάτησε συγχρονισμό: δεν προστίθενται διπλότυπα.

Το `000000000` χρησιμοποιείται αποκλειστικά ως πλασματικό demo ΑΦΜ. Το demo διαθέτει δεδομένα μόνο για αυτόν τον πελάτη. Η μορφή των fixtures είναι υπόθεση εργασίας, όχι δείγμα που παραλήφθηκε από την ΑΑΔΕ.

## Τοπικά δεδομένα και credentials

Στα Windows, οι νέες βάσεις αποθηκεύονται στο `%LOCALAPPDATA%\myInvoicesStarter\`:

```text
demo.sqlite3          # μόνο demo
myinvoices.sqlite3    # πειραματική πραγματική σύνδεση
```

Στο Linux χρησιμοποιείται `$XDG_DATA_HOME/myInvoicesStarter` ή `~/.local/share/myInvoicesStarter`. Μπορείς να ορίσεις διαφορετική βάση με `--db "διαδρομή\new.sqlite3"`. **Μην επιλέξεις υπάρχουσα βάση άλλης εφαρμογής.** Δεν γίνεται μεταφορά δεδομένων από το παλιό myInvoices.

Τα API credentials ορίζονται και ενημερώνονται στα **Στοιχεία πελάτη**, μαζί με το όνομα, το ΑΦΜ και το περιβάλλον. Δεν υπάρχουν κοινά credential fields στην κύρια οθόνη. Στα Windows αποθηκεύονται μέσω **Windows DPAPI** στο υποφάκελο `credentials`, κρυπτογραφημένα για τον τρέχοντα Windows χρήστη. Δεν γράφονται ως απλό κείμενο στη SQLite ή σε προσωρινά αρχεία. Τα κρυπτογραφημένα payloads δεσμεύονται σε client ID, ΑΦΜ και περιβάλλον. Σε Linux/άλλα συστήματα παραμένουν μόνο στη μνήμη και χρειάζεται να οριστούν ξανά μετά το κλείσιμο.

Η μετονομασία διατηρεί το client ID, τα παραστατικά και την πρόοδο. Το ΑΦΜ υπάρχοντος πελάτη μένει σταθερό. Το περιβάλλον μπορεί να διορθωθεί πριν από τον πρώτο αποθηκευμένο συγχρονισμό. Μετά απαιτείται ξεχωριστή εγγραφή για το άλλο περιβάλλον, ώστε να μη συνδεθούν δεδομένα παραγωγής και δοκιμαστικού.

**Η υλοποίηση Windows DPAPI περιλαμβάνει native test, αλλά δεν εκτελέστηκε στο περιβάλλον Linux της ανάπτυξης.** Η αποθήκευση ελέγχθηκε offline με test backend· αυτό δεν υποκαθιστά τη native δοκιμή Windows. Τα αρχεία DPAPI δεν είναι φορητά σε άλλον Windows χρήστη/υπολογιστή· σε τέτοια μεταφορά ορίζονται ξανά τα credentials.

Η βάση περιέχει τοπικά λογιστικά δεδομένα και links που μπορεί να δίνουν πρόσβαση σε παραστατικά· η ίδια η SQLite δεν είναι κρυπτογραφημένη και δεν πρέπει να κοινοποιείται.

## Πραγματική σύνδεση ΑΑΔΕ — ξεχωριστή από το demo

Διαβάστηκε το επίσημο **ERP REST API v2.0.2, Σεπτέμβριος 2026**. Τα ευρήματα, οι πηγές και οι περιορισμοί περιγράφονται στο [docs/AADE_RESEARCH.md](docs/AADE_RESEARCH.md). Ο χρήστης επιβεβαίωσε επιτυχή άντληση πραγματικών παραστατικών στον υπολογιστή του. Οι δοκιμές ανάπτυξης παραμένουν offline, χωρίς χρήση πραγματικών κλειδιών.

1. Κλείσε το demo και άνοιξε το **START_MYINVOICES.bat** ή εκτέλεσε:

```powershell
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -m myinvoices --live
```

2. Πάτησε **Νέος πελάτης**. Συμπλήρωσε όνομα, ΑΦΜ, AADE User ID, Subscription key και το σωστό περιβάλλον. Προεπιλογή της κανονικής λειτουργίας: Παραγωγή ΑΑΔΕ. Τα στοιχεία δοκιμαστικού και παραγωγής δεν είναι εναλλάξιμα. Αν τα κλειδιά εκδόθηκαν από το κανονικό myDATA, διάλεξε Παραγωγή· αν εκδόθηκαν από το dev portal, διάλεξε Δοκιμαστικό.
3. Αν χρησιμοποιείς credentials εξουσιοδοτημένου λογιστή/εκπροσώπου αντί των credentials της ίδιας της οντότητας, επίλεξε **Χρησιμοποιώ κλειδιά λογιστή / εκπροσώπου για άλλον ΑΦΜ**. Η εφαρμογή θα στέλνει `entityVatNumber` με το ΑΦΜ αυτού του πελάτη. Απαιτούνται τα αντίστοιχα δικαιώματα από την ΑΑΔΕ.
4. Πάτησε **Αποθήκευση πελάτη και credentials**. Μελλοντικά τα αλλάζεις από **Στοιχεία πελάτη**.
5. Επίλεξε τον πελάτη και πάτησε **Συγχρονισμός επιλεγμένου**. Πριν από το πραγματικό αίτημα εμφανίζεται επιβεβαίωση με ΑΦΜ και περιβάλλον.

Το απλό άνοιγμα της εφαρμογής και η αποθήκευση πελάτη δεν στέλνουν αιτήματα στην ΑΑΔΕ. Οι πελάτες που προστέθηκαν στο demo βρίσκονται στη demo βάση και δεν μεταφέρονται αυτόματα στη βάση πραγματικής σύνδεσης.

Επιβεβαιωμένες διαδρομές από την ενότητα 4.2.6 της επίσημης τεκμηρίωσης:

```text
Development: https://mydataapidev.aade.gr/RequestDocs
Production:  https://mydatapi.aade.gr/myDATA/RequestDocs
Headers:     aade-user-id, ocp-apim-subscription-key
Query:       mark, nextPartitionKey, nextRowKey
Optional:    entityVatNumber (για λογιστή/εκπρόσωπο)
```

Το `RequestTransmittedDocs` δεν καλείται. Δεν υπάρχουν αυτόματες επαναλήψεις σε rate limit: διατηρείται η πρόοδος και επιλέγεις νέο συγχρονισμό αργότερα. Αν υπάρχει `counterpart/vatNumber` και διαφέρει από το ΑΦΜ του πελάτη, ολόκληρη η σελίδα απορρίπτεται. Αν λείπει, διατηρείται ως άγνωστο και δεν θεωρείται επαληθευμένο. Η υποστήριξη ειδικών ρόλων παραστατικών πρέπει να επεκταθεί με ελεγχόμενα δείγματα.

**Μικτές απαντήσεις RequestDocs:** ακυρώσεις, χαρακτηρισμοί και πληρωμές διατηρούνται ως ξεχωριστές εγγραφές με το XML τους. Η πρόοδος υπολογίζεται από τα MARK των γεγονότων όπου δίνονται, όχι από το MARK του παλιού παραστατικού στο οποίο αναφέρονται. Αν λείπει προαιρετικό MARK μεταβολής, χρησιμοποιείται hash του κανονικοποιημένου XML για idempotency, χωρίς επινόηση MARK. Δεν υλοποιείται ακόμη πλήρης λογιστική ερμηνεία των χαρακτηρισμών ή τρόπων πληρωμής.

Η «Διακοπή» εφαρμόζεται ανάμεσα στις σελίδες/συναλλαγές και μετά το τρέχον HTTP αίτημα. Δεν τερματίζει βίαια το socket· μπορεί να χρειαστεί να λήξει το χρονικό όριο. Το timeout του urllib αφορά αναμονές I/O, δεν είναι εγγυημένο συνολικό χρονικό όριο όλης της λήψης.

## Δομή project

```text
src/myinvoices/
  models.py       # σταθερά μοντέλα και ασφαλή errors
  api.py          # read-only HTTP adapter
  xml_parser.py   # XML, metadata, Decimal ποσά, επίσημο URL
  database.py     # SQLite repositories και ατομικά checkpoints
  sync.py         # υπηρεσία συγχρονισμού χωρίς GUI
  credential_store.py  # credentials ανά πελάτη, Windows DPAPI / session-only
  demo.py         # μόνο συνθετικά XML και offline adapter
  gui.py          # ελληνικό Tkinter, workers και queue
  __main__.py     # εκκίνηση και headless demo check
tests/
  test_sync.py
  test_gui.py
docs/ASSESSMENT.md
```

Η προβολή παραστατικών έχει σελιδοποίηση 200 εγγραφών, ώστε να μην δημιουργεί χιλιάδες Tk widgets μαζί. Network και database operations εκτελούνται σε worker, όχι στα GUI event handlers.

## Διάγνωση αποτυχίας σύνδεσης

**Πιο απλός τοπικός έλεγχος:** άνοιξε `CHECK_AADE.bat` στον ίδιο Windows υπολογιστή όπου αποθήκευσες τον πελάτη. Επίλεξε τον αριθμό του πελάτη και πάτησε Enter. Χρησιμοποιούνται αυτόματα τα αποθηκευμένα credentials και το περιβάλλον του. Δεν χρειάζονται μυστικά cloud, ούτε νέα εισαγωγή κλειδιών. Το παράθυρο μένει ανοικτό για να διαβάσεις τον ακριβή κωδικό HTTP. Στέλνεται ένα αναγνωστικό RequestDocs μόνο για σήμερα, χωρίς αποθήκευση παραστατικών ή μεταβολή του checkpoint.

Αν δεν υπάρχει πελάτης στην κανονική βάση ή δεν έχουν αποθηκευτεί credentials, ο έλεγχος σταματά πριν από οποιοδήποτε αίτημα. Δεν αναζητά δεδομένα στο παλιό legacy πρόγραμμα. Ο τοπικός έλεγχος διαφέρει από τη δοκιμή μέσω cloud που περιγράφεται παρακάτω.

Το παλιό μήνυμα «Η ΑΑΔΕ απέρριψε την πρόσβαση» κάλυπτε HTTP 401 και 403 μαζί. Δεν αποδείκνυε ότι ήταν λάθος τα credentials. Τώρα εμφανίζεται το HTTP status, το περιβάλλον και στάδιο `[credentials]`, `[request]`, `[xml]` ή `[database]`.

- HTTP 401: ελέγχεται αν χρησιμοποιείται το περιβάλλον στο οποίο εκδόθηκαν τα API κλειδιά.
- HTTP 403: ελέγχονται και τα δικαιώματα εκπροσώπησης, το ΑΦΜ οντότητας και περιορισμοί δικτύου.
- `[xml]`: η υπηρεσία απάντησε αλλά ο parser δεν υποστήριξε/δεν αναγνώρισε την απόκριση. Αυτό διαφέρει από αποτυχία ταυτοποίησης.
- `[credentials]`: δεν ολοκληρώθηκε η τοπική ανάγνωση κλειδιών.

Το `diagnostics.jsonl`, δίπλα στη βάση δεδομένων, περιέχει μόνο χρόνο, σταθερό στάδιο, τύπο εξαίρεσης, αριθμό HTTP και θέσεις κώδικα της εφαρμογής. Δεν περιλαμβάνει το μήνυμα της εξαίρεσης, headers, URL, XML, τιμές μεταβλητών ή credentials.

Για ρητά εξουσιοδοτημένο απομονωμένο έλεγχο σύνδεσης υπάρχει `PYTHONPATH=src python -m myinvoices.probe`. Διαβάζει τα ασφαλή environment bindings `MYINVOICES_AADE_USER_ID` και `MYINVOICES_AADE_SUBSCRIPTION_KEY`, κάνει ένα RequestDocs παραγωγής μόνο για τη σημερινή ημερομηνία έκδοσης, και αναφέρει μόνο επιτυχία ή ασφαλές μήνυμα σφάλματος. Δεν γράφει βάση ή παραστατικά. Δεν εκτελείται αυτόματα. Αν τα bindings λείπουν, δεν γίνεται κανένα αίτημα. Μην βάζετε πραγματικά κλειδιά σε αρχεία ή εντολές που θα κοινοποιηθούν.

## Πρακτικές αλλαγές UI στη v0.3

- Το κουμπί **Έλεγχος σύνδεσης API** κάνει ένα αναγνωστικό RequestDocs μόνο για σήμερα, με τα αποθηκευμένα στοιχεία του επιλεγμένου πελάτη, χωρίς αποθήκευση παραστατικών ή αλλαγή checkpoint. Πατάς το κουμπί μόνο όταν θέλεις πραγματικό αίτημα. Στο demo δεν εκτελείται.
- Στο **Μηνύματα και σφάλματα** μπορείς να επιλέξεις κείμενο με το ποντίκι ή Ctrl+A και να το αντιγράψεις με Ctrl+C. Υπάρχουν κουμπιά **Αντιγραφή τελευταίου σφάλματος**, **Αντιγραφή όλων** και **Καθαρισμός**. Το κείμενο δεν είναι επεξεργάσιμο ώστε να μην αλλάξει κατά λάθος η διάγνωση.
- Τα μηνύματα παραμένουν στο πλαίσιο όταν αλλάζει η γραμμή κατάστασης. Διατηρούνται έως περίπου 500 γραμμές ανά συνεδρία. Το κουμπί τελευταίου σφάλματος διατηρεί ολόκληρο το τελευταίο σφάλμα ακόμη και αν περικοπούν παλιές γραμμές.
- Αναζήτηση πελάτη με όνομα ή ΑΦΜ, χωρίς διάκριση κεφαλαίων/πεζών και τόνων. Διπλό κλικ στον πελάτη ανοίγει τα στοιχεία του.
- Η καρτέλα **Ακυρώσεις / Μεταβολές** εμφανίζει έως 200 νεότερες εγγραφές. Όλες διατηρούνται στη βάση. Ακυρωμένα παραστατικά σημειώνονται στην κύρια λίστα χωρίς διαγραφή.

### Το συγκεκριμένο σφάλμα «Μη αναμενόμενη απόκριση RequestDocs»

Σημαίνει ότι το εξωτερικό XML στοιχείο δεν ήταν το αναμενόμενο RequestedDoc. Δεν είναι το ίδιο σφάλμα με μη υποστηριζόμενες ακυρώσεις/χαρακτηρισμούς και δεν αποδεικνύει σωστή ή λανθασμένη ταυτοποίηση. Η νέα έκδοση εμφανίζει `[XML_ROOT=...]` μόνο για γνωστά τεχνικά ονόματα ρίζας, διαφορετικά `UNKNOWN`. Δεν εκτυπώνει XML ή κείμενο της απάντησης. Δεν δέχεται άγνωστη ρίζα ως επιτυχή κενό συγχρονισμό. Η αιτία της πραγματικής απόκρισης παραγωγής δεν έχει ακόμη αναπαραχθεί.

### Αναβάθμιση τοπικής βάσης

Το schema αναβαθμίζεται από 1 σε 2 προσθέτοντας πίνακα μεταβολών, χωρίς διαγραφή υπαρχόντων πινάκων/πελατών/παραστατικών/checkpoints. Πριν την προσθήκη δημιουργείται ξεχωριστό SQLite backup, επαληθεύεται με quick_check και διατηρείται δίπλα στη βάση ως `*-schema1-backup-*.sqlite3`. Αν η αναβάθμιση αποτύχει, δεν ολοκληρώνεται η αλλαγή schema. Το backup περιέχει λογιστικά δεδομένα και δεν πρέπει να κοινοποιείται. Η παλιά έκδοση schema-1 δεν ανοίγει τη νέα βάση schema-2· για επιστροφή χρησιμοποιείται ξεχωριστό αντίγραφο του backup, χωρίς αντικατάσταση της νέας βάσης.

## v0.3.1 — η απάντηση XML_ROOT=string

Ο αναφερθείς φάκελος `string` υποστηρίζεται όταν περιέχει escaped/serialized XML: αποκωδικοποιείται και το εσωτερικό έγγραφο ελέγχεται κανονικά ως RequestedDoc. Υποστηρίζονται έως δύο επίπεδα wrapper, με τους ίδιους ελέγχους μεγέθους, DTD/entities και εγκυρότητας. Κενό `string` ή απλό κείμενο αναφέρονται ως `XML_STRING=EMPTY` / `TEXT` και δεν αντιμετωπίζονται ως επιτυχημένη κενή άντληση. Εσωτερικό ResponseDoc αναφέρεται ως σφάλμα υπηρεσίας.

Για HTTP σφάλματα διατηρείται τόσο το HTTP status όσο και τυχόν αριθμητικοί κωδικοί ΑΑΔΕ από ResponseDoc. Το σώμα ελέγχεται μόνο μέχρι 64 KiB, χωρίς εμφάνιση των μηνυμάτων ή δεδομένων του. Ο χειρισμός διασταυρώθηκε με το upstream commit `1244dd9296606f63f1390d88c2faeaf8049b5d09`, που διορθώνει σιωπηλά κενά αποτελέσματα σε απαντήσεις σφάλματος.

Δεν υπάρχει πρόσθετη κλήση ελέγχου εξουσιοδότησης πριν το RequestDocs. Με κλειδιά του ίδιου του πελάτη αφήνετε την επιλογή εκπροσώπησης κλειστή: δεν προστίθεται entityVatNumber. Προστίθεται μόνο όταν το επιλέξετε ρητά για χρήση λογιστή/εκπροσώπου άλλου ΑΦΜ.
