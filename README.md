# Οργάνωση αρχείων — Windows 11

Δωρεάν, τοπική εφαρμογή Python/Tkinter στα ελληνικά. Δεν χρησιμοποιεί cloud ή υπηρεσίες δικτύου. Άδεια MIT.

## Εκτέλεση από πηγαίο κώδικα

Εγκαταστήστε Python 3.11 ή νεότερη με Tcl/Tk (ο επίσημος installer των Windows το περιλαμβάνει). Από τον φάκελο του έργου:

```bat
py -3 main.py
```

Δεν απαιτούνται εξωτερικές βιβλιοθήκες για εκτέλεση ή δοκιμές.

## Χρήση

1. Προσθέστε όσους φακέλους ή ρίζες δίσκων θέλετε μέσω του επιλογέα φακέλων («Αυτός ο υπολογιστής»).
2. Επιλέξτε έναν υπάρχοντα φάκελο προορισμού. Προτιμήστε ξεχωριστό φάκελο σε δίσκο με αρκετό ελεύθερο χώρο.
3. Πατήστε **Σάρωση αρχείων**. Δεν δημιουργούνται ή μεταβάλλονται αρχεία κατά τη σάρωση.
4. Ελέγξτε όλες τις σελίδες. Εμφανίζονται πηγή, ακριβής προτεινόμενος προορισμός και μέγεθος για κάθε αρχείο.
5. Επιλέξτε αντιγραφή (προεπιλογή) ή μετακίνηση και πατήστε **Οργάνωση αρχείων…**. Απαιτείται επιβεβαίωση.

Τα αρχεία οργανώνονται ανά τύπο και έτος τελευταίας τροποποίησης, στην τοπική ζώνη ώρας, π.χ. `Excel/2026/πίνακας.xlsx`. Όσα δεν έχουν αναγνωρισμένη επέκταση πηγαίνουν στα `Λοιπά`. Ίδια ονόματα παίρνουν αρίθμηση `(1)`, `(2)`: διατηρούνται όλα, ακόμη και αν έχουν ίδιο περιεχόμενο. Αν δημιουργηθεί σύγκρουση μετά την προεπισκόπηση, η συγκεκριμένη ενέργεια αποτυγχάνει χωρίς αντικατάσταση. Μετά από εκτέλεση απαιτείται νέα σάρωση.

Εξαιρούνται ο προορισμός και οι απόγονοί του, συμβολικοί σύνδεσμοι, junctions/reparse points και γνωστοί φάκελοι συστήματος, όπως Windows, Program Files, ProgramData, AppData, Recovery και κάδος ανακύκλωσης. Τα μη προσβάσιμα αρχεία αναφέρονται ως προειδοποιήσεις. Επικαλυπτόμενες πηγές σαρώνονται μία φορά. Η εφαρμογή δεν πρέπει να εκτελείται ως διαχειριστής.

Η αντιγραφή γίνεται πρώτα σε προσωρινό αρχείο στον προορισμό. Η μετακίνηση αφαιρεί την πηγή μόνο μετά την επιτυχή δημοσίευση του αντιγράφου. Ελέγχονται μέγεθος και χρόνος τροποποίησης πριν και μετά την αντιγραφή. Δεν παρέχεται αναίρεση: η ακύρωση σταματά την τρέχουσα/επόμενη ενέργεια, διατηρώντας τις ολοκληρωμένες. Δοκιμάστε πρώτα αντιγραφή μικρού δείγματος και κρατήστε ανεξάρτητο backup πριν από μετακίνηση.

Το πλήρες ιστορικό εκτέλεσης αποθηκεύεται σε UTF-8 JSONL στο `%LOCALAPPDATA%\FileOrganizer\logs`. Περιέχει διαδρομές, λειτουργία, αποτέλεσμα και σφάλματα. Το πλαίσιο ιστορικού εμφανίζει τις πρόσφατες εγγραφές. Η σάρωση/αντιγραφή εκτελείται σε νήμα εργασίας και η προεπισκόπηση σε σελίδες των 250 γραμμών.

Δεν διατηρούνται NTFS ACLs, alternate data streams ή όλες οι ιδιότητες των αρχείων: διατηρείται το περιεχόμενο και το Date Modified. Κλειδωμένα αρχεία αναφέρονται ως σφάλματα. Δεν πρόκειται για εργαλείο migration συστήματος ή backup. Αποφύγετε ενεργά αρχεία και ταυτόχρονες αλλαγές στις επιλεγμένες διαδρομές κατά την εκτέλεση.

## Νέο περιβάλλον χρήσης

- Καθαρή φωτεινή εμφάνιση, γραμματοσειρά Segoe UI στα Windows, κάρτες ρυθμίσεων/προεπισκόπησης και μπλε κύριες ενέργειες.
- Οδηγός τεσσάρων βημάτων: **Επιλογή φακέλων → Σάρωση → Προεπισκόπηση → Οργάνωση**. Το τρέχον βήμα επισημαίνεται.
- Σύνολο αρχείων, συνολικό μέγεθος σε B/KB/MB/GB και αριθμός προειδοποιήσεων. Ο πίνακας διαθέτει εναλλασσόμενες γραμμές, κύλιση και σελιδοποίηση. Επιλέξτε γραμμή για πλήρεις, αντιγράψιμες διαδρομές στα πεδία «Από» και «Προς».
- Κάθε βασική ενέργεια/επιλογή έχει **?**: αφήστε τον δείκτη επάνω του για λίγο ή μετακινηθείτε σε αυτό με **Tab**. Η επεξήγηση κλείνει με **Esc**, απομάκρυνση του δείκτη ή αλλαγή εστίασης. Το πληκτρολόγιο αποκαλύπτει αυτόματα το στοιχείο όταν βρίσκεται εκτός του ορατού τμήματος.
- Η κατάσταση και το ιστορικό ξεχωρίζουν **επιτυχία**, **προειδοποίηση** και **σφάλμα** με ελληνική ένδειξη και χρώμα. Η πρόοδος και η ακύρωση παραμένουν ορατές στο κάτω μέρος του παραθύρου.
- Σε στενά παράθυρα οι ενότητες εμφανίζονται κατακόρυφα με κύλιση. Σε μεγαλύτερα, οι ρυθμίσεις βρίσκονται αριστερά και η προεπισκόπηση δεξιά. Μπορείτε να αλλάξετε το μέγεθος του παραθύρου. Η εκκίνηση αναγνωρίζει το Windows display scaling πριν δημιουργηθεί το παράθυρο Tk.
- Η οργάνωση ενεργοποιείται μόνο μετά από ολοκληρωμένη σάρωση με αποτελέσματα. Άδειες/ακυρωμένες σαρώσεις και σφάλματα έχουν σαφή μηνύματα. Κατά την εργασία οι ρυθμίσεις κλειδώνουν και η ακύρωση παραμένει διαθέσιμη.

Τα tooltips και το θέμα χρησιμοποιούν μόνο Tkinter/ttk, χωρίς εξωτερικά εικονίδια, γραμματοσειρές ή πρόσθετες εξαρτήσεις, και συμπεριλαμβάνονται αυτόματα στο EXE. Οι αλγόριθμοι και οι έλεγχοι ασφαλείας στο `organizer/core.py` παραμένουν αμετάβλητοι.

## Δοκιμές

```bat
py -3 -m unittest discover -s tests -v
```

Οι δοκιμές δημιουργούν αποκλειστικά προσωρινούς φακέλους. Καλύπτουν προεπισκόπηση, κατηγορίες/έτος, εξαιρέσεις, επικαλύψεις, διπλά ονόματα, συγκρούσεις μετά τη σάρωση, αλλαγμένες πηγές, αντιγραφή, μετακίνηση, ακύρωση και ιστορικό.

Οι πρόσθετες δοκιμές UI ελέγχουν πραγματικά widgets Tk: κατάσταση κουμπιών, έλλειψη επιλογών, άδεια/ακυρωμένη προεπισκόπηση, μετρητές, σελίδες, διαδρομές, επιβεβαίωση και αντιγραφή σε προσωρινό φάκελο μέσω του GUI, ιστορικό, σφάλματα, tooltips με hover/Tab/Esc και προσαρμογή διάταξης/κλίμακας.

Σε Linux χωρίς οθόνη οι δοκιμές πραγματικών widgets σημειώνονται ως **skipped**, ενώ οι δοκιμές πυρήνα και βοηθητικών συναρτήσεων εκτελούνται κανονικά. Για πλήρη εκτέλεση χρειάζεται X display, π.χ. `xvfb-run -a python -m unittest discover -s tests -v` εφόσον έχετε Xvfb. Με `FILE_ORGANIZER_REQUIRE_GUI_TESTS=1` η απουσία οθόνης προκαλεί αποτυχία, ώστε το build στα Windows να ελέγχει υποχρεωτικά και το GUI.

## Αυτοτελές Windows EXE

Σε **Windows 11** με εγκατεστημένη Python, τρέξτε `build.bat`. Το script δημιουργεί virtual environment, εγκαθιστά PyInstaller, εκτελεί τις δοκιμές και παράγει `dist\FileOrganizer.exe`. Η πρώτη δημιουργία απαιτεί Internet για λήψη των εργαλείων. Ο τελικός χρήστης χρειάζεται μόνο το EXE, χωρίς Python ή σύνδεση Internet. Το PyInstaller πρέπει να τρέξει σε Windows για Windows EXE· δεν υποστηρίζεται cross-compilation από Linux. Το παραγόμενο EXE δεν έχει ψηφιακή υπογραφή και ενδέχεται να εμφανίζεται ειδοποίηση SmartScreen.

Επαληθεύτηκαν 19 δοκιμές σε Linux με Python 3.13/Tk 8.6 και εικονική οθόνη, χωρίς παραλείψεις: πυρήνας, widgets, διάταξη σε στενό/ευρύ παράθυρο και αυξημένη κλίμακα. Οπτικός έλεγχος έγινε επίσης σε Tk 8.6. Η τελική εμφάνιση Segoe UI, το πραγματικό Windows display scaling (ιδίως σε πολλαπλές οθόνες), τα junctions και το παραγόμενο EXE χρειάζονται επιπλέον δοκιμή σε Windows 11.


## Αυτόματη παραγωγή EXE στο GitHub

Το workflow [Windows EXE](https://github.com/gkampanis/legend/actions/workflows/windows-exe.yml) ξεκινά αυτόματα με κάθε push στο `file-organizer` ή χειροκίνητα από το **Run workflow**. Δεν απαιτείται εγκατάσταση εργαλείων στον υπολογιστή του τελικού χρήστη.

Ο runner `windows-latest` εγκαθιστά Python 3.12 x64 και το PyInstaller του `requirements-build.txt`, εκτελεί όλες τις υπάρχουσες δοκιμές (με υποχρεωτική παρουσία GUI) και χτίζει με `--onefile --windowed`. Το `scripts/verify-windows-exe.ps1` εκκινεί το ίδιο το παραγόμενο EXE, ελέγχει το Windows GUI subsystem, τον ελληνικό τίτλο, την παρουσία των controls και την απόκριση του παραθύρου, αποθηκεύει screenshot και απαιτεί κανονικό κλείσιμο με κωδικό εξόδου 0. Δεν σαρώνει ή μετακινεί αρχεία. Ένας άδειος ή μη λειτουργικός έλεγχος δεν επιτρέπει δημοσίευση EXE.

Μετά από επιτυχή επαλήθευση διατίθενται:

- **FileOrganizer-Windows-x64**: Actions artifact με `FileOrganizer.exe` και SHA-256 checksum, διαθέσιμο για 90 ημέρες.
- **Windows-GUI-verification**: screenshot του πραγματικού EXE και αναφορά JSON, διαθέσιμα για 30 ημέρες.
- **GitHub Release**, εφόσον επιτρέπεται `contents: write`: το EXE, το checksum και τα στοιχεία επαλήθευσης ως απευθείας assets. Κάθε εκτέλεση έχει μοναδικό tag `file-organizer-build-<run_number>-<run_attempt>` και το Release σημειώνεται ως latest. Αν η δημοσίευση Release αποτύχει, το επαληθευμένο EXE παραμένει στο Actions artifact και το σφάλμα φαίνεται στο βήμα δημοσίευσης.

Όταν έχει δημοσιευτεί επιτυχώς Release, ο σταθερός σύνδεσμος είναι:

[Λήψη FileOrganizer.exe](https://github.com/gkampanis/legend/releases/latest/download/FileOrganizer.exe)

Κατεβάστε και ανοίξτε το EXE: δεν χρειάζεται Python ή εκτέλεση scripts. Το αρχείο παραμένει χωρίς ψηφιακή υπογραφή. Το screenshot του runner είναι στοιχείο οπτικού ελέγχου, ενώ οι δοκιμές ελέγχουν τις αλληλεπιδράσεις του GUI. Ο Windows runner χρησιμοποιεί Windows Server· η τελική εμφάνιση σε κάθε ρύθμιση Windows 11 μπορεί να διαφέρει.
